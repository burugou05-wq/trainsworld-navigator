# Trainsworld 調査レポート

## 公式に確認したこと

2026年11月14日に開発者の公式説明と、同日に配信されていたゲームの公開ファイルを確認した。

- ゲームには通常・高速線路と通常・高速車両がある。系統作成時に停車駅を指定し、コピーから系統グループ、急行と各停、枝線や途中折返しを設定できる。高・中・低需要区分の配車や目標間隔の設定がある。 [開発者のゲーム説明](https://anita.garden/projects/trainsworld/)
- ゲーム内の保存一覧からファイルをダウンロードできる。公開クライアントの保存一覧では、操作の英語名は「Download as a file」。現在のプレイのエクスポート処理もあり、生成される名前は `trainsworld-<セーブ名>-day-<日>.save`。 [ゲーム本体](https://anita.garden/trainsworld/) · [調査時の公開クライアント](https://anita.garden/trainsworld/assets/index-BD54sRwk.js)
- 公開クライアントは gzip を展開して `TWG1` を検査する。公開実行ファイルには駅ID、グループ、駅の明示リンク、停車順、経路、折返し、需要別運行頻度を参照する処理がある。公式の駅複合体判定は、ホームの近接、手動リンク、駅施設のつながりを使う。 [調査時の公開ワーカー](https://anita.garden/trainsworld/assets/clock.worker-hdc6c_8C.js)
- 公式説明にはゲーム内データの ODbL 表記がある。検索した範囲では、このゲームに対応する公開ソースリポジトリ、公式セーブ仕様書、外部アプリ向け同期APIを確認できなかった。ゲームの公開配信ファイルとシミュレーターは照合に使った。配布物には独立した読み込み処理を収録した。 [公式のデータ出典](https://anita.garden/projects/trainsworld/#sources)

## 添付ファイルから確認したこと

`trainsworld-tokyo-2-day-195.save` は 44,513 バイト。gzip 展開後は 122,326 バイト。ヘッダーに東京の開始コード `tyo` がある。旧原点や別地域の既定値もヘッダーに含まれるため、対象地域は駅座標と開始コードから判断した。鉄道バイナリの駅座標はグローバルなメルカトル座標。

281駅、32運行系統、683線路、7グループ。グループに属さない11系統を独立した路線として数えると18路線。32系統が建設済みで、全系統で停車順に沿った連続経路を確認した。系統ごとの停車区間は片方向269本。明示的な駅間リンク、駅施設ポリゴン、片方向系統は、このファイルには見つからなかった。公式の駅複合体は229組で、うち26組が複数ホーム。

`fares` に USD 基準の料金曲線、基準地域、倍率がある。所要時間の参考になる設定は、需要別編成数、停車・折返し秒数、車両数、記録された運行頻度等。ゲームの時間帯ごとの実効頻度・混雑・遅れは、このアプリの推定時間には含めていない。

## 設計

- **UIとビルド**。HTML・CSS・JavaScript のモジュールで実装。ページ数と動的な状態が少なく、同じ画面を Web と両拡張で使うため、React、Vite、Tailwind は採用しなかった。IndexedDB にファイルのコピーを保存する。gzip はブラウザー標準 API で展開する。 [DecompressionStream](https://developer.mozilla.org/en-US/docs/Web/API/DecompressionStream)
- **経路**。Dijkstra 法。駅複合体ごとに乗車可能な系統と方向を保持し、乗車後は系統・方向・停車位置を状態とする。途中停車せず通過する駅には乗車辺を作らない。乗換の評価は時間と回数の辞書順を切り替える。別モードの最良候補や主要系統を一つ外した候補を集める。候補生成は全経路を順位順に列挙する方式ではない。
- **地図**。MapLibre GL JS は地理的なベースマップとベクタータイルの重ね合わせに適し、Leaflet は地点と線の表示や操作の組み込みに向く。この実装は保存座標だけで動く Canvas の概略図。外部タイルの取得が不要で、ブラウザー拡張にも同じ構成を使える。 [MapLibre GL JS](https://maplibre.org/maplibre-gl-js/docs/) · [Leaflet](https://leafletjs.com/reference.html)
- **拡張機能**。双方 Manifest V3。Chrome は `side_panel` とサービスワーカー。Firefox は `sidebar_action` とバックグラウンドスクリプト。ブラウザー標準の操作で開閉とサイズ変更を行う。ゲームページへのスクリプト注入やホスト権限、クラウド接続は使用しない。 [Chrome](https://developer.chrome.com/docs/extensions/reference/api/sidePanel) · [Firefox](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/Chrome_incompatibilities)

## 別のセーブを検証する場合

対応範囲を広げるには、未読込のセーブ本体とゲームの版が必要。運行系統の設定画面またはゲーム内路線図があると、追加された記録の意味を照合できる。時間の精度を上げるには、対象系統・需要区分・方向が分かる実走行の停車時刻か公開された時刻表が必要。実際の課金と照合するには、特急料金や乗換割引が適用された経路のゲーム内運賃例が必要。
