# セーブ形式の仕様

ゲームの公開処理とエクスポートを照合して得た互換形式。ゲームのバージョン更新で追加領域が変わる可能性がある。対象実装は、添付の東京セーブと照合済みの鉄道用フィールドを読み込む。

## コンテナー

ファイル先頭の `1f 8b` で gzip を判定する。展開後と非圧縮形式は同じ構造。

| 順序 | 内容 |
|---|---|
| 1 | ASCII `TWG1` |
| 2 | UTF-8 ヘッダーのバイト数、32-bit little-endian |
| 3 | UTF-8 JSON。識別子 `game=anitabuilder` と `format=1` を確認 |
| 4 | 軌道バイナリ `TWT4`・`TWT5`・`TWT6` |

`clock` はゲーム内秒。日数は86400で割った整数部。`start` は開始都市。`fares` に基本値、距離曲線、地域倍率がある。地域・財務・人口等の設定は経路データの対象外。

## 軌道バイナリ

固定ヘッダーは4バイトの識別子と、経度・緯度を表す little-endian の float64 各1個。後続は符号なし可変長整数（1バイトにつき下位7ビット、上位ビットが継続）。符号付きの値は ZigZag（0, −1, 1, −2 …）。文字列はバイト数と厳密な UTF-8。座標差分は投影座標の1/1000単位。球半径は6,371,008.8 m。TWT4は正距円筒、TWT5はランベルト正角円錐、TWT6はグローバルなメルカトル座標。TWT6では旧原点を加算しない。

1. 通行側のフラグ。
2. ノード表。個数の後、順序がノードID。前ノードからの X/Y 差分、高さ、フラグがあり、条件付きでホーム長と名前を持つ。ホーム長のあるノードが駅。
3. 線路表。個数の後、順序が線路ID。A は直前の A からの差分、B は A からの差分。フラグに軌道数と建設状態があり、`0x40` は高速線路。中間点の個数と、点ごとの座標差分、詳細形状フィールド2個が続く。
4. 系統表。個数の後、順序が系統ID。名前、24-bit RGB、添付でゼロの設定3個、建設状態、需要別編成数3個、停車・折返しの各 0.1 秒単位、編成両数、停車駅IDの差分列、方向付き線路列。線路列の値を `v` とすると、線路ID差分は偶数で `floor(v/4)`、奇数で `−floor(v/4)−1`、方向は `((v >> 1) ^ v) & 1`。

## 追加領域

軌道バイナリ末尾に `ERA1` または `ERA2` の追加記録が付くことがある。末尾構造は「追加記録本体、長さ（32-bit little-endian）、4バイトのタグ」。公式ゲームのネットワーク照合と同じ境界で、駅・線路の読み込み範囲から外す。長さが軌道ヘッダーに食い込む場合は読み込みを停止する。 [公式ゲームの処理](https://anita.garden/trainsworld/assets/clock.worker-hdc6c_8C.js)

長さはセクションごとの構造から判定する。

| タグ | 読み取る値 |
|---|---|
| `LUI1` | 系統の記号 |
| `LNK1` | 明示リンクの両端の駅ID |
| `LAU1` | 需要区分別の目標間隔（秒） |
| `LHS1` | 高速車両の系統ID |
| `LOW1` | 片方向の系統ID |
| `LSL1` | 系統の最高速度設定（km/h） |
| `LTW1` | 系統の複線に関する設定。経路検索には使用しない |
| `BLD1` | 駅施設の名称と境界座標 |
| `LFR2` | 船着場の着岸位置とフェリー系統の航路・速度 |
| `LBS2` | バス系統の道路経路と建設状態 |
| `LRT1` | 需要別の運行頻度3値（float32 のビット列を可変長整数に格納）。後続に方向別時刻関連の記録 |
| `LGR1` / `LGL1` | 系統のグループID、グループの名称・記号・色 |
| `LPH1` / `LSP1` | 系統IDごとの3値。検索では使用しない |
| `LBD1` | 駅・線路・系統の建設日配列 |

## 復元と推定

- 駅IDを保持する。名前は表示・検索に使う。複数ホームを含む駅は、明示リンクまたは座標・ホーム形状から構成する。添付では駅中心100 m、ホーム間50 mの判定を公式の結果と照合した。曲線ホームでは線路から近似したホーム形状を使用する。
- 方向付き線路の連続性、建設状態、実際の停車駅ID順を照合する。駅の通過だけで停車を追加しない。停車区間距離は保存された線路端点と中間点から概算する。
- 通常のセーブでは線路距離から走行時間を推定する。高速車両の上限は高速線路320 km/h・普通線路160 km/hとし、系統の速度制限と方向別の加減速を適用する。条件を満たす高速系統は高需要の配車数と運行頻度から往復時間を推定し、折返しと停車を除いた時間を駅間に配分する。`.twtime` では、照合できた系統にゲームの方向別・需要帯別計算値を使う。待ち時間は運行頻度から求め、頻度ゼロの時間帯は運行再開を待つ。
- 添付ファイルの運賃は、保存された距離曲線 `[(0, 1.55), (20, 4.1), (100, 14)]` に距離を当てはめ、保存倍率7.3を使う推定モデル。距離は区間ごとにメートルへ丸めて集計する。経路別の実際の課金や100 km超の最終料金は未検証。
- 32 MiBの入力制限、96 MiBの展開制限、個数上限、参照先と座標の検査がある。軌道・系統設定やタグが対応範囲外の場合はエラーで通知する。
