# Trainsworld 互換性調査（204日目）

公式のゲーム説明と2026年11月14日に配信されていたゲームの読み込み処理を参照した。東京195日目・204日目の実セーブを読み込み、別の検証環境で個別に設定を変更して再出力したファイルも比較した。公式ファイルは照合に使用した。 [公式説明](https://anita.garden/projects/trainsworld/) · [ゲーム](https://anita.garden/trainsworld/) · [調査したゲームワーカー](https://anita.garden/trainsworld/assets/clock.worker-hdc6c_8C.js)

| ゲームの仕様 | Navigatorでの利用 | 確認方法 |
|---|---|---|
| 駅改良 | 折返し設備・パーク＆ライド・待合室・待避線を駅詳細に表示 | 204日目の37駅分の改良記録を公式の出力と照合。ビット4〜7は追加バイトを消費しない |
| 改名・手動リンク | ホームID、駅施設・座標とリンクを使って乗換を復元。駅名は検索・表示に使用 | 204日目の明示リンク `24 ↔ 170`、東京の9ホームの一括改名を照合 |
| 片方向ホーム | 駅詳細に表示 | 設定のみを変更した再出力で駅フラグ `0x200` を照合。系統の片方向とは別設定 |
| 停車順・環状・片方向系統 | 停車位置ごとに列車の方向を保持 | 両セーブの停車順を公式値と照合。片方向・環状は探索テストで検証 |
| 系統別速度制限 | 距離から計算する推定所要時間の速度上限に使用 | 82 km/hに変更した再出力で `LSL1` を照合 |
| 駅施設の敷地 | 敷地または境界付近に接するホームの乗換を推定 | `BLD1` の頂点を公式値と照合。曲線ホームは近似 |
| 座標形式 | TWT4・TWT5・TWT6を自動判定し緯度経度を復元 | 公式の座標変換で出力したTWT4・TWT5を読み込み、東京の座標と駅のまとまりを比較 |
| フェリー | 着岸場所を照合できる建設済み航路を検索に使用 | 検証環境で作った2港の航路を、計画時と建設後の両方で読み込み |
| バス | 対応する道路記録は読み込んで系統を表示 | `LBS2` の建設前後を比較。自動生成停留所は道路データにも依存するため検索対象外 |

204日目では **298駅、35系統、線路718本、駅のまとまり239組**。駅ID・名前・座標、線路端点、系統名・色・グループID・停車順・方向付き線路・運行頻度、全239組の駅IDの組み合わせが公式結果と一致した。新設の佐倉線・練馬川越線・狭山線を取り込んだ。回帰テストでは既存195日目と204日目の両方を検証する。

東京を「東京駅」へ改名した検証用セーブでは、9つのホームIDと全乗換グループが一致した。Web検索で「東京駅」と入力して横浜行きの候補を表示できた。ユーザーのセーブは読み取りだけで検証した。

195日目・204日目を含む自動テスト8件が通過。ChromeのWeb版（PC幅・スマートフォン幅）と拡張機能ページ、FirefoxのWeb版で204日目を取り込み、東京から横浜への検索も通過した。

区間の精密な所要時間、混雑・信号による遅れ、ゲームが再計算する迂回や方向別停車位置、路面電車固有の設定、未解明の新規タグは引き続き検証対象。ファイル位置を確定できない領域は読み飛ばすと停車順の誤読につながるため、そのタグまたは駅IDを通知する。
